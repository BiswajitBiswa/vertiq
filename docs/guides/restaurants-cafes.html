Restaurants and cafés

Bring regulars back, size offers to each guest's usual bill, and stop promoting what's out of stock.

benchmarked mapping tested

Questions you can ask

  • Will this guest be back within 30 days? predict_event(target="", window_days=30)
    No type column is mapped, so every bill is a visit and target "" means any visit.
  • How big will their next bill be? predict_value(target="", window_days=45)

Working example

from datetime import datetime, timedelta
from vertiq import plugins, rules
from vertiq.mapping import Mapping, apply, repair
from vertiq.tasks import predict_event, predict_value

# rows: your export as a list of dicts, e.g. list(csv.DictReader(open("export.csv")))
mapping = Mapping.parse({"entity": "Guest Phone (masked)", "time": "Bill Date", "type": None, "value": "Net Amount", "group": "Outlet", "attrs": ["Channel", "Covers", "Payment Mode"], "date_format": "%d/%m/%Y"})
m, notes = repair(mapping, rows)      # the rows settle column names, value types and the date format
ds, problems = apply(m, rows)         # any row that didn't load is named, never guessed

@plugins.feature("food")
def weekend_regular(entity, before, cut):   # only events before the cutoff: no peeking
    recent = [e for e in before if e.at >= cut - timedelta(days=90)]
    weekend = sum(1 for e in recent if e.at.weekday() >= 5)
    return {"weekend_share_90": weekend / len(recent) if recent else 0.0}

task = predict_event(ds, target="", window_days=30, pack="food")
print(task.status, task.report())     # "trained" only if it beat the baseline on held-out entities
if task.status == "trained":
    print(task.score("G-1042"))  # the chance, and what raises or lowers it

size = predict_value(ds, target="", window_days=45, pack="food")
print(size.status, size.report())

flags = rules.run(ds, [
    rules.repeat(1, type="refund"),   # two refunds for the same guest in a day
])
print(flags["summary"])

This exact code runs in the test suite (tests/test_guides.py) against generated rows in these column names.

Domain knowledge: weekend_regular

Weekend regulars and weekday office crowds behave differently; tell the model which is which.

Checks

  • rules.repeat(1, type="refund"): two refunds for the same guest in a day

Also useful

  • uplift: who a WhatsApp message brings back, learned from a held-out control group
  • value.train_bill: whether an offer grows or shrinks the bill it brings
  • affinity: dishes ordered together, each guest's next dish, refill rhythms
  • offers.spend_more: a spend-more threshold sized to each guest's usual bill
  • inventory: never promote what is out of stock; flag slow movers

Before you rely on it

  • Message only guests who opted in; train only on guests who agreed to analytics.
  • Hold out a control group on every campaign, or uplift has nothing to learn from.

Evidence so far

  • benchmarked Customer return: learned model vs recency formula, 5 seeds
  • benchmarked Uplift: finds who a message brings back; offer effect on the bill recovered within 1 point
  • benchmarked Insights: planted first-order pattern found 5/5, no false findings in noise
  • mapping tested Hospitality tables in the Vertiq LM mapping test
