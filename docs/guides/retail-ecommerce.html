Retail and e-commerce

Spot shoppers going quiet, recommend the next product from real baskets, and reorder before stock runs out.

benchmarked mapping tested

Questions you can ask

  • Will this shopper order again within 60 days? predict_event(target="order", window_days=60)
    Order Type holds order or return; returns are negative amounts and never count as a visit.
  • What will their next order be worth? predict_value(target="order", window_days=60)

Working example

from datetime import datetime, timedelta
from vertiq import plugins, rules
from vertiq.mapping import Mapping, apply, repair
from vertiq.tasks import predict_event, predict_value

# rows: your export as a list of dicts, e.g. list(csv.DictReader(open("export.csv")))
mapping = Mapping.parse({"entity": "Customer ID", "time": "Order Date", "type": "Order Type", "value": "Order Value", "group": "Store", "attrs": ["Category", "Coupon"], "date_format": "%Y-%m-%d"})
m, notes = repair(mapping, rows)      # the rows settle column names, value types and the date format
ds, problems = apply(m, rows)         # any row that didn't load is named, never guessed

@plugins.feature("retail")
def returns_share(entity, before, cut):   # only events before the cutoff: no peeking
    orders = [e for e in before if e.type == "order"]
    returns = [e for e in before if e.type == "return"]
    return {"return_share": len(returns) / max(1, len(orders))}

task = predict_event(ds, target="order", window_days=60, pack="retail")
print(task.status, task.report())     # "trained" only if it beat the baseline on held-out entities
if task.status == "trained":
    print(task.score("C-88213"))  # the chance, and what raises or lowers it

size = predict_value(ds, target="order", window_days=60, pack="retail")
print(size.status, size.report())

flags = rules.run(ds, [
    rules.repeat(1, type="return"),   # two returns by the same shopper on the same day
])
print(flags["summary"])

This exact code runs in the test suite (tests/test_guides.py) against generated rows in these column names.

Domain knowledge: returns_share

Shoppers who return a lot buy differently; returns are events of their own type.

Checks

  • rules.repeat(1, type="return"): two returns by the same shopper on the same day

Also useful

  • affinity: products bought together and by the same people; each shopper's next product
  • inventory: reorder points from sales velocity and lead time; slow movers; margins
  • insights: patterns tested before they are shown (false-discovery control)

Before you rely on it

  • Returns are negative-value events; they never count as a visit.
  • A model learned on one season can drift; the gate retrains only if the new one is no worse.

Evidence so far

  • benchmarked Customer return and uplift scenarios (5 seeds)
  • mapping tested Retail sales tables, a domain Vertiq LM never saw in training
