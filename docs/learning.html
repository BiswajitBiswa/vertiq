How it learns

Every model is a test it could have failed

Three rules run through every task: features use only the past, a share of entities is held out entirely, and a model replaces the baseline only when it wins on those held-out entities.

No peeking at the future

Held out by entity

About a fifth of entities, chosen by a hash of their id, never appear in training. A machine or a guest is never in both halves, so the score says how the model does on someone new.

Against the obvious rule

For events, the baseline is recency: the more recently it happened, the likelier again. For values, it is "same as last time". Vertiq reports both, and ships only when it wins.

Against the model you run

A retrained model must also be no worse than the current one on the same held-out entities, so a bad week of data can't replace a good model.

Cause, not correlation

Insights are tested before they are shown

Vertiq checks many patterns at once (the day of a first visit, the size of a first bill, what was ordered first). Each candidate gets a p-value, and the family is filtered with Benjamini-Hochberg at a 10% false-discovery rate, so the more places it looks, the stronger a pattern must be. Groups smaller than 20 are never compared. In the benchmark it found the planted pattern in 5/5 seeds and reported 0 false item patterns in noise.

Consent. The host decides who may train a model. Train only on people who agreed, never on anyone who opted out; scoring a business's own customers is use, not training.
