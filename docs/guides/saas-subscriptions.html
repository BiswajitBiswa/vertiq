SaaS and subscriptions

Predict which accounts will cancel or downgrade, and what the next renewal will be worth.

not yet tested

Questions you can ask

  • Will this account cancel within 30 days? predict_event(target="cancel", window_days=30)
  • What will the next renewal be worth? predict_value(target="renewal", window_days=365)

Working example

from datetime import datetime, timedelta
from vertiq import plugins, rules
from vertiq.mapping import Mapping, apply, repair
from vertiq.tasks import predict_event, predict_value

# rows: your export as a list of dicts, e.g. list(csv.DictReader(open("export.csv")))
mapping = Mapping.parse({"entity": "Account ID", "time": "Event Time", "type": "Event", "value": "MRR Change", "group": "Plan", "attrs": ["Seats", "Region"], "date_format": "%Y-%m-%dT%H:%M:%S"})
m, notes = repair(mapping, rows)      # the rows settle column names, value types and the date format
ds, problems = apply(m, rows)         # any row that didn't load is named, never guessed

@plugins.feature("saas")
def usage_drop(entity, before, cut):   # only events before the cutoff: no peeking
    now = sum(1 for e in before if e.type == "login" and e.at >= cut - timedelta(days=30))
    prev = sum(1 for e in before if e.type == "login"
               and cut - timedelta(days=60) <= e.at < cut - timedelta(days=30))
    return {"login_ratio": (now + 1) / (prev + 1)}

task = predict_event(ds, target="cancel", window_days=30, pack="saas")
print(task.status, task.report())     # "trained" only if it beat the baseline on held-out entities
if task.status == "trained":
    print(task.score("acct_7f2"))  # the chance, and what raises or lowers it

size = predict_value(ds, target="renewal", window_days=365, pack="saas")
print(size.status, size.report())

flags = rules.run(ds, [
    rules.repeat(7, type="payment_failed"),   # a second failed payment within a week
])
print(flags["summary"])

This exact code runs in the test suite (tests/test_guides.py) against generated rows in these column names.

Domain knowledge: usage_drop

Product usage falling is the classic early sign; count logins this month against last.

Checks

  • rules.repeat(7, type="payment_failed"): a second failed payment within a week

Also useful

  • insights: tested patterns, for example which first-week actions predict staying

Before you rely on it

  • Usage events can be very frequent; aggregate them to daily counts before mapping.
