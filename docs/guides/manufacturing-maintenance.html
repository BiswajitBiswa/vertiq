Sector guides / Manufacturing and maintenance

Manufacturing and maintenance

Predict breakdowns, catch skipped preventive maintenance and parts used beyond the bill of materials.

benchmarked mapping tested

Your records in Vertiq's terms

entity
machine or asset
group
plant or line
profile
generic (set your own windows with verticals.register)

Questions you can ask

  • Will this machine break down within 30 days? predict_event(target="breakdown", window_days=30)
  • What will the next repair cost? predict_value(target="breakdown", window_days=90)

Working example

from datetime import datetime, timedelta
from vertiq import plugins, rules
from vertiq.mapping import Mapping, apply, repair
from vertiq.tasks import predict_event, predict_value

# rows: your export as a list of dicts, e.g. list(csv.DictReader(open("export.csv")))
mapping = Mapping.parse({"entity": "Equipment No", "time": "Work Order Date", "type": "Order Type", "value": "Cost", "group": "Plant", "attrs": ["Fault Code", "PM Done", "Technician Note"], "date_format": "%Y-%m-%d"})
m, notes = repair(mapping, rows)      # the rows settle column names, value types and the date format
ds, problems = apply(m, rows)         # any row that didn't load is named, never guessed

@plugins.feature("plants")
def skipped_pm_60(entity, before, cut):   # only events before the cutoff: no peeking
    return {"skipped_pm_60": sum(1 for e in before if e.type == "pm"
                                and e.attrs.get("PM Done") == "no"
                                and e.at >= cut - timedelta(days=60))}

task = predict_event(ds, target="breakdown", window_days=30, pack="plants")
print(task.status, task.report())     # "trained" only if it beat the baseline on held-out entities
if task.status == "trained":
    print(task.score("EQ-602"))  # the chance, and what raises or lowers it

size = predict_value(ds, target="breakdown", window_days=90, pack="plants")
print(size.status, size.report())

flags = rules.run(ds, [
    rules.repeat(30, key="Fault Code", type="breakdown"),   # the same fault again within 30 days
    rules.exceeds({"SEAL": {"seal kit": 1}}, key="Fault Code"),   # more parts than the bill of materials allows
    rules.too_short("Technician Note", 2),   # notes too short to learn from
])
print(flags["summary"])

This exact code runs in the test suite (tests/test_guides.py) against generated rows in these column names.

Domain knowledge: skipped_pm_60

Skipped preventive maintenance raises breakdown risk; the benchmark plants exactly this.

Checks

  • rules.repeat(30, key="Fault Code", type="breakdown"): the same fault again within 30 days
  • rules.exceeds({"SEAL": {"seal kit": 1}}, key="Fault Code"): more parts than the bill of materials allows
  • rules.too_short("Technician Note", 2): notes too short to learn from

Also useful

  • inventory: spare-part reorder points from usage and lead time

Before you rely on it

  • exceeds() reads parts from event.items: build those events directly from your parts table.

Evidence so far

  • benchmarked Breakdowns: baseline 0.674 → general model 0.735 → with the plugin 0.767 AUC (5 seeds)
  • mapping tested Manufacturing tables, a domain Vertiq LM never saw in training
