Salons, gyms and appointment services

Learn each client's rhythm, catch the ones slipping, and time reminders to when they are due.

benchmarked not yet tested

Your records in Vertiq's terms

entity
client or member
group

salon / gym

Questions you can ask

  • Will this member come in within 14 days? predict_event(target="visit", window_days=14)
    Kind holds visit or follow-up; Plan End, Due and Done are ISO dates.

Working example

from datetime import datetime, timedelta
from vertiq import plugins, rules
from vertiq.mapping import Mapping, apply, repair
from vertiq.tasks import predict_event, predict_value

# rows: your export as a list of dicts, e.g. list(csv.DictReader(open("export.csv")))
mapping = Mapping.parse({"entity": "Member No", "time": "Check-in", "type": "Kind", "value": "Amount", "group": "Branch", "attrs": ["Service", "Trainer", "Plan End", "Due", "Done"], "date_format": "%d-%m-%Y"})
m, notes = repair(mapping, rows)      # the rows settle column names, value types and the date format
ds, problems = apply(m, rows)         # any row that didn't load is named, never guessed

@plugins.feature("fitness")
def plan_days_left(entity, before, cut):   # only events before the cutoff: no peeking
    ends = [e.attrs.get("Plan End") for e in before if e.attrs.get("Plan End")]
    if not ends:
        return {}
    return {"days_to_plan_end": (datetime.fromisoformat(ends[-1]) - cut).days}

task = predict_event(ds, target="visit", window_days=14, pack="fitness")
print(task.status, task.report())     # "trained" only if it beat the baseline on held-out entities
if task.status == "trained":
    print(task.score("M-311"))  # the chance, and what raises or lowers it

flags = rules.run(ds, [
    rules.overdue("Due", "Done", tolerance_days=7, type="follow-up"),   # a follow-up session that is more than a week late
])
print(flags["summary"])

This exact code runs in the test suite (tests/test_guides.py) against generated rows in these column names.

Domain knowledge: plan_days_left

A membership about to lapse changes everything; pass the plan end date as an attribute.

Checks

  • rules.overdue("Due", "Done", tolerance_days=7, type="follow-up"): a follow-up session that is more than a week late

Also useful

  • churn: a visit-rhythm model shared across businesses, corrected per branch
  • uplift: who a reminder brings back, against a control group

Before you rely on it

  • A check-in without a payment still proves a visit; map it as its own type.

Evidence so far

  • benchmarked Customer return scenario (irregular rhythms, 5 seeds)
