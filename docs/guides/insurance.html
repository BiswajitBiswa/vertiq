Predict renewals and lapses, flag repeat or duplicate claims for review.

Questions you can ask

  • Will this policy see a claim within 90 days? predict_event(target="", window_days=90)
    Each row is a claim and no type column is mapped, so target "" means any claim.
  • How large will the next claim be? predict_value(target="", window_days=365)

Working example

from datetime import datetime, timedelta
from vertiq import plugins, rules
from vertiq.mapping import Mapping, apply, repair
from vertiq.tasks import predict_event, predict_value

# rows: your export as a list of dicts, e.g. list(csv.DictReader(open("export.csv")))
mapping = Mapping.parse({"entity": "Police Nr", "time": "Loss Date", "type": None, "value": "Claim Amount", "group": "Agence", "attrs": ["Cover", "Channel"], "date_format": "%d/%m/%Y"})
m, notes = repair(mapping, rows)      # the rows settle column names, value types and the date format
ds, problems = apply(m, rows)         # any row that didn't load is named, never guessed

@plugins.feature("insurance")
def claims_365(entity, before, cut):   # only events before the cutoff: no peeking
    return {"claims_365": sum(1 for e in before if e.at >= cut - timedelta(days=365))}

task = predict_event(ds, target="", window_days=90, pack="insurance")
print(task.status, task.report())     # "trained" only if it beat the baseline on held-out entities
if task.status == "trained":
    print(task.score("POL482910"))  # the chance, and what raises or lowers it

size = predict_value(ds, target="", window_days=365, pack="insurance")
print(size.status, size.report())

flags = rules.run(ds, [
    rules.repeat(14, key="Cover"),   # a second claim on the same cover within two weeks, for review
])
print(flags["summary"])

This exact code runs in the test suite (tests/test_guides.py) against generated rows in these column names.

Domain knowledge: claims_365

Recent claim frequency is the strongest known signal; make it explicit.

Checks

  • rules.repeat(14, key="Cover"): a second claim on the same cover within two weeks, for review

Before you rely on it

  • Flags are for human review, never automatic denial.
  • Keep protected attributes (age, gender, religion, caste) out of features.

Evidence so far

  • mapping tested Insurance tables, a domain Vertiq LM never saw in training
